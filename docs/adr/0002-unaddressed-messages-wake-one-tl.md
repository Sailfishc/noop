# 没有 @ 的消息只叫醒频道的 TL

要让频道像聊天，就得有人接没有 @ 任何人的消息，而「理解上下文再决定说不说」每条消息都要花一次模型调用。我们决定每个频道最多指定一个现有 Agent 当 TL，默认没有；人发的没有 @ 的顶层消息只叫醒 TL，它可以不说话、自己回答或转交。Agent 发的消息从不叫醒任何 Agent。

## Considered Options

- 每条消息叫醒频道里所有 Agent，各自判断（Raft 的做法）：最自然，但花费随 Agent 数量增长，还会出现几个 Agent 同时接话。
- 所有 Agent 排队依次接话（Cindy 群聊的默认）：一个问题得到几份相似的回答。
- 只有被 @ 才回答（原来的做法）：最省，但人必须自己当路由，这正是「像派活」的来源。

## Consequences

TL 以发消息的人的名义做事，沿用现有的派活权限和确认卡，不另开一套权限。没有 TL 的频道行为不变。
