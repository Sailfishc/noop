Remi：更像聊天的对话流和线程
Nov 12, 2026 · @sailfishcc
结论
对话流的基本单位从「任务卡」改成「消息」，任务只是叠在对话上的一种状态。聊天、进度和产出三样东西分开放：聊天在对话流，进度是原地更新的清单，产出在右侧工作面板打开。
具体有五处变化：
1. 问一句就回一句，不建任务卡。连着说几句话，Agent 记得上文。
2. 频道可以指定一个 TL。没 @ 任何人的消息由它读了上下文再决定说不说、转给谁。
3. 定时到点不再以你的名义发消息。Agent 被安静地叫醒，有变化才说话。
4. 产出挂在消息上，点开在右侧看。频道有一个「文件」列表，任务结束后文件还找得到。
5. 进度是一张计划清单，任务卡上显示「3/7 加当前步骤」，不再为进度发消息。
代价是花费和注意力：聊得多就多用额度，TL 每条没 @ 的消息都要判断一次。所以 TL 默认不开，按频道选。
这份文档是四轮提问（27 个决定，全部按推荐）的汇总。确认后交给开发线程，分五个 PR 落地。

设计
1. 对话流：消息是单位，任务是状态
• Agent 的回答是主对话流里的一条普通消息，不建卡。私聊是一条平的连续对话流。
• 只有当这件事改了东西、要等待或要验收时，才在原地出现任务卡。任务的过程进它的线程，结果在主对话流里留一行。
• 状态变化（开始、等待、完成）显示在任务卡上，不再各发一条消息。
• 回答超过 12 行时折叠，点开看全文。
2. 一段对话：连着说话不用重新 @
• 一个人和同一个 Agent 连续的消息共用同一个运行时会话，所以 Agent 记得上文。
• 空闲 2 小时后这段对话结束。再说话时开新会话，并从最近的消息里恢复上下文。
• 频道里回答之后，输入框上出现「继续和 @x 聊 ×」的标记，保留 10 分钟，可以点掉。标记在时，不写 @ 的消息也发给它。这是明示的，不靠系统猜。

4. TL
• TL 是给现有 Agent 加的频道角色，不是新的一类 Agent。每个频道最多一个，默认没有。
• 它被叫醒后有三种反应：不说话（界面上什么都不出现）、自己回答、转给更合适的 Agent 或点名某个人。
• 它接话算作发消息的人 @ 了它。那个人没有权限派它时，它不接。它转给别的 Agent 时沿用现有的委派和确认卡规则。
• 它在一个频道里共用同一段对话，连续几条消息等 20 秒合并成一次叫醒。
• 它被叫醒时能看到频道里正在进行的任务，所以能提醒「这块 @某某 正在改」。
• 做事准则：频道里有更合适的 Agent 时把活派出去，没有时才自己做。这是写给它的准则，服务器不强制。
5. 触发：到点不再替你说话
• 提醒和触发器到点时，不以任何人的名义发消息。Agent 被安静地叫醒。
• 它检查后有变化才说话，说的是它自己的话。
• 线程里只留一行可展开的记录，例如「已检查 12 次，最近一次 10:02，没有变化」。
6. 产出
• 产出挂在消息上。普通回答也能带文件，任务的产出就是它那些消息带的产出。
• 对话流里产出只占一行卡片。点开在右侧工作面板里看：文档渲染好，图片放大，可以切换版本。
• 每个频道有一个「文件」列表，汇总这个频道里所有产出。它是从消息里算出来的，不新建存储。
• 暂不做：把文件钉给 Agent 当长期上下文。
7. 进度
• 进度就是运行时自己的待办清单（Codex 的 todo_list、Claude Code 的 TodoWrite），Remi 不新增命令。
• 任务卡上显示「3/7 加当前步骤」，完整清单在工作面板里，原地更新。
• 没有清单的运行时退回只显示当前步骤。
• 别人看进度：现有任务视图的每一行加上「3/7」和负责的 Agent，不新做任务板。
• Agent 只在有话值得说时才说话，不为进度发消息。
8. 工作面板
右侧面板从「线程面板」变成「工作面板」，打开的是一件事，有三部分：它的对话、计划清单、产出。点任务卡、点产出卡、点线程都打开它。

代价和风险
• 额度：TL 每条没 @ 的消息都要判断一次，包括它最后选择不说话的那些。靠同一段对话和 20 秒合并来压低，但不是零。
• TL 说错话或乱插话：它是模型判断，会有该说没说和不该说却说了的情况。频道可以随时取消 TL。
• 长会话变贵变糊：一段对话越长，每次调用越贵，早先的内容也可能被运行时压缩。2 小时空闲结束是折中，数字要用过再调。
• 和「注意力只花在对齐、拍板、验收」的张力：更多聊天意味着更多消息要看。对策是进度和状态不再发消息，TL 沉默时不出现，净消息量应该下降，但这点没有数据，要上线后看。
• 没验证的：三种运行时在长会话里连续接收多条消息的真实表现；20 秒和 10 分钟、2 小时这三个数字都是估的。
落地顺序
五个 PR，每个都能单独上线，前一个不依赖后一个。
1. 静默触发：到点不以人的名义发消息，一行记录；状态变化进任务卡。直接解决「线程里全是自己的 ⏰」。
2. 一段对话和私聊：连续消息共用会话，私聊变成平的连续对话流。
3. 频道回答和 TL：回答是顶层消息，「继续和 @x 聊」标记，频道 TL。
4. 产出挂消息：回答也能带文件，产出在工作面板打开。
5. 计划清单和频道文件：工作面板里的清单，任务卡和任务视图上的「3/7」，频道「文件」列表。
需要记 ADR 的三个决定：连续消息共用一个会话；没 @ 的消息只叫醒一个 TL 而不是所有 Agent；触发不是消息。
运行时适配层：先试接 oar
oar 是 Raft 团队开源的运行时统一接口（Apache-2.0，Raft 自己的 server 和 daemon 都在用）。一段对话、插话、计划清单、额度窗口这几样它都已经做了，而我们现在是在 src/runtimes.ts 里一家一家手写。
在第 2 个 PR 之前做一天试接，验证四件事：
1. 在 Bun 下能跑（它要求 Node 24，没验证过）。
2. 会话能恢复。
3. 运行中能插话。
4. 我们加的参数能原样传进去：只读模式、Codex 的环境变量策略、Claude 的工具白名单。
四件都通过，就锁定一个版本，在现有事件接口后面替换掉手写的适配层，并记一个 ADR。任何一件不通过就维持现状。它还没到 1.0，三周涨了三十多个小版本，所以必须锁版本。第 1 个 PR 不受影响。
